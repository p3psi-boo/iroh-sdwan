# 策略运行时架构

本文是 V2 策略运行时的当前概览。历史实施计划、交接记录和 Phase 0 测量报告位于[历史档案](archive/README.md)，不作为部署或接口规范。

## 边界与唯一事实源

- WIT ABI V1 的唯一来源是 `crates/ironet-policy-abi/wit/ironet-policy.wit`；guest 通过 `ironet-policy-sdk` 导出纯 `decide` 接口，不获得网络、文件、时钟或宿主密钥能力。
- 生产配置、信任根和热切换语义以[配置参考](配置参考.md)为准；guest 构建与 WIT 校验以[开发与测试](开发与测试.md)为准。
- 宿主实现位于 `src/protocol/v2/policy/` 与 `src/protocol/v2/policy_tick.rs`。`ironet-policy-core` 是 builtin guest 与原生参考后端共享的纯策略逻辑。

## 决策流水线

```text
遥测 + 宿主规则基线 + 上一轮效用
  → PolicyInputV1
  → live PolicyBackend（可选 shadow PolicyBackend）
  → 宿主 guardrail / 节点出口裁决
  → EffectiveActionV1
  → 数据面执行
```

策略只能提出候选动作；宿主计算效用、执行资源与安全约束，并生成可进入数据面的最终 `EffectiveActionV1`。shadow slot 有独立状态和观测结果，不写入数据面。

## 策略来源与回退

`[autotune].policy` 有三种现行取值：

1. `native`：显式选择不加载外部文件的保守宿主规则；
2. `builtin`：默认值，在进程内以
   `CorePolicyBackendV1(PolicySpecV1::builtin())` 执行；不构造 Wasmtime
   engine，也不加载嵌入的 `builtin.wasm`；
3. 绝对 `.wasm` 路径：外部单文件组件。

只有外部 live/shadow `.wasm` 组件会进入 `PolicyLoader`/Wasmtime，并经
manifest、摘要、签名或 digest pin、ABI 和资源预算校验。外部 live 组件在
初始加载失败时回落到原生 `builtin`；热加载失败保留 last-known-good；运行中
slot 连续故障会被隔离并由宿主规则基线维持转发。显式 `native` 才使用
`native-conservative@1`。`builtin.wasm` 仍作为可复现 guest 与
CorePolicy 的 bit-exact 对照产物保留，不是默认 daemon 路径。

状态和启动日志同时报告来源与后端：默认 builtin 的 status 为
`policy.policy_source=builtin`、`policy.live.backend=native`、
`policy.live.policy_id=bandit-vivace@1`，其 `policy.live.policy_version` 与
`policy.live.state_schema` 来自 `PolicySpecV1`，`policy.live.module_digest`
是该 canonical spec 的 BLAKE3 digest，且没有 signer。显式 native 的 identity
为 `native-conservative@1`、schema `0`、digest `native`；外部组件才报告
`policy.live.backend=wasm`、package digest 和 signer。详细约束见[配置参考](配置参考.md#autotunewasm)。

## 状态、热切换与可观测性

每个 peer 的策略状态由宿主持久化；同一策略标识和兼容的 state schema 可保留状态。外部 `.wasm` 文件在后台验证和编译，切换发生在采样边界，坏文件不替换 last-known-good。运行状态会暴露 live/shadow backend、策略身份、健康度、故障和 clamp 信息。

## 运维与验证

- 使用 `ironet policy keygen|sign|inspect|verify|replay` 管理和验证组件。
- `ironet policy replay --policy builtin` 刻意通过 verified loader 运行嵌入的
  `builtin.wasm` guest，用于与 in-process core 的 bit-exact 对照；这不会改变
  daemon 默认 `builtin` 的原生执行路径。
- 修改 `[autotune]` 或 `[autotune.wasm]` 后重新 seal 配置，再通过守护进程 reload 应用。
- builtin guest 的可复现构建、WIT 校验和 workspace 测试命令见[开发与测试](开发与测试.md)。

算法原理、效用函数和网络实验背景仍见[自适应调优方案](自适应调优方案.md)；其中标注为历史的 JSON 产物与旧实施步骤不适用于当前部署。
