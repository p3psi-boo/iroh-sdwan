# Ironet Protocol V2 性能验证

## 原则

1. 只测试正式 `ironetd` 的 V2 数据面，不保留或对比旧协议进程。
2. 每次吞吐结论同时包含 iperf3 原始 JSON、两端 perf report、两端火焰图和自动调优日志。
3. 先执行零流量 preflight；管理面路由、Yggdrasil `200::/7`、`tun-ygg` 地址/link/qdisc 必须在前后完全一致。
4. profile 进程只允许信号发送给经过 `/proc/PID/cmdline` 精确验证的 perf 和 benchmark PID；PID 为空、0、1、2 均 fail closed。
5. 使用 CPU allowed-list 的后半区并降低优先级，避免 profile 本身成为测量瓶颈。

## 本地 V2 门禁

```bash
cargo test --lib
cargo clippy --all-targets -- -D warnings
scripts/check-v2-only.sh
IRONET_V2_PROFILE_PREFLIGHT_ONLY=1 scripts/profile-v2-netns.sh
IRONET_V2_PROFILE_PREFLIGHT_ONLY=1 scripts/profile-v2-subnet-netns.sh
```

本地负载 profile 仅在 preflight、进程 guard、管理面快照和清理 canary 全部通过后执行：

```bash
scripts/profile-v2-netns.sh
scripts/profile-v2-subnet-netns.sh
```

`nix develop` 默认 shell 已包含 `perf`、`iperf3`、FlameGraph（`flamegraph.pl`/`stackcollapse-perf.pl`）、`ethtool`、`ping`、`taskset`/`flock` 与 coreutils；脚本需要 `sudo -n`。

## netem 场景矩阵

`scripts/profile-v2-netns-matrix.sh` 按目录顺序运行每个场景并汇总为 `aggregate.json`/`aggregate.csv`；`--list` 打印目录。目录列为
`name|direction|a_delay|a_jitter|a_delay_corr|a_loss|a_loss_corr|a_rate|a_queue|b_…|seconds|timeline|description`，其中 `seconds` 为 0 时使用 `IRONET_V2_MATRIX_SECONDS`，`timeline` 为空表示静态场景。

```bash
scripts/profile-v2-netns-matrix.sh --list
IRONET_V2_MATRIX_SCENARIOS=home-100d-50u-upload,p2-wuwei-lossy-upload scripts/profile-v2-netns-matrix.sh
# 每个场景在 TCP 饱和测试后追加 4 路 UDP 竞争流，aggregate 记录 Jain 指数与离散度：
IRONET_V2_MATRIX_FAIRNESS_SECONDS=15 IRONET_V2_MATRIX_FAIRNESS_PER_STREAM_MBIT=20 \
IRONET_V2_MATRIX_SCENARIOS=home-100d-50u-upload scripts/profile-v2-netns-matrix.sh
# 只看调优行为、不采 CPU profile（动态场景建议这样跑）：
IRONET_V2_MATRIX_PERF=0 IRONET_V2_MATRIX_SCENARIOS=step-bw-100-20-100,burst-loss-0-5-0 scripts/profile-v2-netns-matrix.sh
```

### 动态场景（时间线）

`IRONET_V2_PROFILE_TIMELINE` 让路径条件在 overlay 饱和阶段中途改变，用来验收自动调优的收敛、过冲与恢复，而不是稳态吞吐：

```bash
IRONET_V2_PROFILE_PERF=0 IRONET_V2_PROFILE_SECONDS=60 \
IRONET_V2_PROFILE_A_TO_B_DELAY_MS=8 IRONET_V2_PROFILE_A_TO_B_RATE_MBIT=100 IRONET_V2_PROFILE_A_TO_B_QUEUE_PACKETS=1500 \
IRONET_V2_PROFILE_CONCURRENT_PING_INTERVAL_MS=100 \
IRONET_V2_PROFILE_TIMELINE='20:a_rate=20,a_queue=300;40:a_rate=100,a_queue=1500' \
scripts/profile-v2-netns.sh
```

- 语法 `<offset_s>:<key>=<value>[,<key>=<value>];…`，偏移是饱和阶段开始后的整秒，严格递增且小于时长；键为 `a_delay a_jitter a_delay_corr a_loss a_loss_corr a_rate a_queue` 与 `b_*`，取值规则与静态变量一致，启动前全部校验。
- 每个步骤对被触及方向重新下发完整 netem 状态（`tc qdisc replace`，回到 0 即为直通队列），前后各采一次 qdisc 计数与两端 `status`，记录到 `timeline.tsv`（含实际生效毫秒）。
- `summary.json` 新增：`saturation_started_at`（对齐锚点）、`timeline`、`segments`（每段的 overlay 均值/中位/末 5 s 均值、`settle_seconds`、ping p50/max、该段 netem 实际发送/丢弃计数）、`overlay_interval_series`（iperf3 逐秒）、`overlay_ping_series`（逐秒 p50/max）、`tuning_status`（守护进程每 10 个采样一条的调优状态）和 `autotune_tap.{a,b}`（schema 4 的每秒 telemetry/decision/utility/learner/wire-cost JSON，含 BBR3 snapshot、参数发布/生效 generation 和相对饱和起点偏移；离线回放兼容 schema 3）。`autotune.{a,b}` 汇总效用均值/末 10 样本均值/p10、最终应用层与 BBR 动作、动作切换、learner 回滚、控制器 generation 待生效样本数、收敛时间、FEC 几何分布、接收侧 residual loss 与 latency sojourn；矩阵 CSV 取流量发送端对应的一组指标。
- `settle_seconds` 定义：该段内吞吐首次连续 3 秒落在末 5 秒中位数 ±10% 内的时刻（相对段起点）；`null` 表示该段未收敛或过短。
- 目录内置动态场景：`step-bw-100-20-100`、`burst-loss-0-5-0`、`rtt-shift-40-120`、`policer-onset`、`wifi-degrade`。路径迁移（`path_epoch` 变化）需要第二条 underlay 链路，尚未纳入。
- `IRONET_V2_PROFILE_PERF=0` 跳过 perf 与火焰图；此时 `summary.json` 的 `perf_enabled=false`、`*_perf_lost_samples=null`。结论性吞吐/CPU 数字仍须使用默认的 perf 运行。

### 护栏内固定动作实验

`IRONET_AUTOTUNE_FORCE` 只用于 oracle/回归实验，把应用层策略动作固定下来而不关闭运行时护栏。脚本会显式把该变量传入两个 netns 守护进程，把原始对象保存为 `autotune-force.json`，并写入 `summary.json.autotune_force`；每条 tap 的 `force_applied=true` 可证明实际启用：

```bash
IRONET_AUTOTUNE_FORCE='{"fec":"8+1","train_target_bytes":32768,"bulk_quantum_cells":2}' \
IRONET_V2_PROFILE_PERF=0 scripts/profile-v2-netns.sh
```

支持字段：

- `fec`: `null`/`"off"`，`"DATA+PARITY"`，或 `{"data_cells":8,"parity_cells":1}`；最高冗余 50%。
- `train_target_bytes`: 自动夹紧到 8–64 KiB。
- `bulk_quantum_cells`: 自动夹紧到 1–4；存在延迟队列时强制为 1。
- `cover_profile`: `idle`、`live-broadcast`、`interactive-video`、`generic-h3-bulk`。
- `cover_overhead_per_mille`: 不超过运行时上限；队列、丢包、CPU、Idle 或积压触发 cover 抑制时仍强制为 0。

可靠 relay/CPU 限制时 FEC 仍关闭；紧急丢包时强制 `fec=off` 仍由基线保护覆盖。未知字段、非法几何和空对象均在启动时失败，避免 oracle 样本静默使用错误动作。

固定动作 oracle 用 `scripts/autotune-oracle.sh`。它对 FEC × train × quantum × cover profile/overhead 笛卡尔积逐个运行选定矩阵场景，保留未固定的当前策略作为 baseline，但只在固定动作中选 oracle；支持 `IRONET_V2_ORACLE_RESUME=1` 断点续跑。网格通常关闭 perf，动作实现改动先单独跑一次带双端火焰图的场景：

```bash
nix develop -c env \
  IRONETD_BIN=$PWD/target/profiling/ironetd \
  IRONET_BIN=$PWD/target/profiling/ironet \
  IRONET_V2_ORACLE_SCENARIOS=wifi-lan-light,p2-wuwei-lossy-upload \
  IRONET_V2_ORACLE_FEC_GRID=off,4+1,8+1,8+2 \
  IRONET_V2_ORACLE_TRAIN_GRID=8192,32768,65536 \
  IRONET_V2_ORACLE_QUANTUM_GRID=1,2,4 \
  scripts/autotune-oracle.sh
```

结果为 `oracle.json`。由于效用有任意零点且允许为负，主 `regret` 定义为 `(U_oracle-U_baseline)/max(1,abs(U_oracle))`；仅当 oracle 为正时额外给出传统的 `ratio_regret = 1-U_baseline/U_oracle`。

当前已验证的热路径包括：连续 PacketTrain、Cell recycling、driver-owned DATAGRAM mailbox、单 Future RX burst drain、TUN gather write、FEC encoder workspace 复用和动态 TX/RX budget。

## p2–p6 / 子网验收

- underlay 基线：p2 ↔ p6 的运营商 IPv4/IPv6。
- overlay endpoint：p2 ↔ p6 的 V2 地址。
- subnet：p2 → `11.6.1.48`，下一跳为 p6。
- 每组依次执行单流、4 流和反向 4 流；测试窗口、CPU pin、iperf3 参数保持一致。
- 输出 overlay/underlay goodput 比、CPU/Gbit、重传、RTT/loss、PMTU、queue sojourn、FEC wire overhead 和 Repair 成功率。

## p2–wuwei-ws 丢包验收

wuwei-ws 只通过运营商公网 IPv6 与 p2 建立 direct locator；明确排除 `200::/7`。测试健康、自然丢包和受控 netem 三组：

- 自动调优应根据对端反馈决定 `off`、`6+1`、`6+2` 或 `4+2`，而不是读取用户配置。
- 拥塞证据必须压制 FEC/Repair，DERP 等可靠 underlay 必须关闭应用 FEC。
- 验收比较 goodput、retrans、恢复 Cell、waste、Repair 延迟和总 wire overhead；“开启 FEC 后带宽更高”只在接收 goodput 提升且总 wire overhead 可解释时成立。

## 火焰图判定

优化前后使用同一拓扑、构建产物、持续时间和 CPU 集合。除吞吐外，重点追踪：

- QUIC 主状态锁争用和 producer↔driver 唤醒；
- `memmove`/allocator 与 Cell encode；
- ChaCha/AES open/seal；
- reassembly/FEC hash、过期清扫和 TUN write；
- transit 节点是否保持 label lookup + shim decrement，不做 Record/FEC decode。

单轮结果受宿主后台负载影响时只记录为样本，不宣称回归或提升；至少重复一轮，并用 underlay 基线解释环境变化。
