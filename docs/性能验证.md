# 数据面性能验证

## 本地微基准

```bash
nix develop -c cargo run --release --example dataplane_bench -- 1000000
```

固定记录以下结果，重构前后必须使用相同 CPU governor、构建配置和迭代次数：

- IPv4/TCP 报文解析 ns/op
- peer 队列 enqueue/dequeue roundtrip ns/op
- 双路由 FlowRouter 选择 ns/op
- 64 KiB 乱序重组 ns/op

### 2026-08-15 本机对比

相同主机、`--release`、1,000,000 次主循环；旧基线为 `614c6c6`，重组项各执行 100 次。该表用于发现代码回归，不替代跨机器吞吐测试。

| 热路径 | `614c6c6` | 当前实现 | 变化 |
|---|---:|---:|---:|
| IPv4/TCP 解析 | 9.5 ns/op | 8.5 ns/op | -10.5% |
| peer 队列往返 | 189.8 ns/op | 127.3 ns/op | -32.9% |
| 双路由 FlowRouter | 230.5 ns/op | 160.0 ns/op | -30.6% |
| 64 KiB 乱序重组 | 109,093.1 ns/op | 8,103.7 ns/op | -92.6%（约 13.5 倍） |

队列基线是共享互斥队列；当前实现是有界 MPMC producer ingress 加单写者 consumer。重组基线为逐字节占用位图，当前实现为切片复制与不相交区间合并。

## p2–p6 广域网矩阵

每对节点分别测试 IPv4、IPv6、DERP 和 overlay transit；每组覆盖 0%、1%、5% 丢包以及 NAT/纯路由模式。

```bash
iperf3 -c TARGET -P 1 -t 30
iperf3 -c TARGET -P 8 -t 30
iperf3 -c TARGET -R -P 8 -t 30
ping -c 100 TARGET
```

同时采集：

```bash
perf stat -a -e cycles,instructions,cache-misses,context-switches,syscalls:sys_enter_read,syscalls:sys_enter_write -- sleep 30
perf record -F 199 -g -- ironet run CONFIG
```

验收指标：

1. IPv6 黑洞时，IPv4/DERP 首次连接不再等待一次完整连接超时。
2. direct 丢包或 RTT 显著劣化时，DERP/overlay transit 能接管；恢复后遵守 hold-down，不逐包抖动。
3. 单直接路由流量不产生 delivery tag，不争用 DeliveryCoordinator。
4. TUN 使用 GSO/GRO、批量收发和最多 8 个多队列 Router shard。
5. 吞吐测试中每包系统调用、context switch 和 CPU cycles/packet 相比旧数据面下降。

补充检查：单健康直连必须保持 `delivery_tagged_packets_total` 不增长；单 transit 路由仍必须保留 receiver-confirmed tracking，以便备用路径重连前完成容量再学习。

### 2026-08-15 网络命名空间验收

最终镜像通过 `docker-flowrouter`、`docker-fec`、`docker-mesh`、`docker-relay`、
`docker-derp`、`docker-wan`、`docker-mtu` 和 `docker-congestion`。拥塞隔离样本在同一
12 Mbit/s、12 ms 邻接上并行运行 8 条 TCP 流时得到：

- 空闲 ping p95：27.64 ms；负载 ping p95：77.57 ms；
- TCP goodput：4.32 Mbit/s；
- QUIC 不可抢占发送缓冲：7,007 B，不超过 8 KiB；
- Bulk 被延迟流抢占 19 次；应用队列最终为 0，未增加队列丢弃或过期丢弃。

发送端只在 QUIC 内保留 8 KiB 浅缓冲。64 KiB TUN super-packet 的剩余 wire
datagram 保留在可抢占的单写者调度器中，因此批处理吞吐与交互尾延迟不再由同一个
不可抢占 FIFO 互相牺牲。
