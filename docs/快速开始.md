# 快速开始：两节点静态拓扑

本文使用两个节点建立最小的三层覆盖网络。两个节点通过固定的公网 UDP 地址互相引导，覆盖地址分别为 `21.0.0.1/32` 和 `21.0.0.2/32`。示例中的地址、端口和 endpoint ID 均应替换为实际值。

## 1. 前提

每个节点均需满足：

- Linux、`iproute2`、`/dev/net/tun`；
- 可使用 `sudo`，或为守护进程提供 `CAP_NET_ADMIN`；
- 每个新节点至少能通过固定 UDP 地址或 iroh relay 连接一个 bootstrap peer；开启发现时需要访问默认 N0 QAD/relay，或在 `[relay]` 中配置至少两个自建 URL；
- 正式连接可先走 relay，并在同一连接上完成打洞和透明直连升级；直连失效时会回退 relay 并重新发现；
- 覆盖地址和已发布的 LAN 前缀不与本地网络或其他节点前缀重叠。

若节点需要转发到本地 LAN，主机还需要开启 IPv4/IPv6 转发。使用包或 `scripts/install.sh` 安装时，`systemd/90-ironet.conf` 会设置相应 sysctl；仍应在上线前执行 `doctor` 验证。

## 2. 安装

安装 Debian 包：

```bash
sudo dpkg -i ./ironet_0.1.0_amd64.deb
```

或从源码安装：

```bash
nix develop -c cargo build --locked --release
sudo scripts/install.sh
```

安装完成后，二进制位于 `/usr/bin`（Debian 包）或 `/usr/local/bin`（安装脚本）。以下示例统一使用 `ironet`。

## 3. 创建身份和网络 ID

先在节点 A 执行初始化。交互过程中填写覆盖地址、可选的 LAN 前缀和引导 peer；首次执行时不填写网络 ID，由程序生成。

```bash
sudo ironet init \
  --config /etc/ironet/config.toml \
  --state-dir /var/lib/ironet
```

记录输出中的以下值：

```text
network_id = ...
endpoint_id = ...
```

在节点 B 执行相同命令，并把节点 A 的 `network_id` 传给 `--network-id`：

```bash
sudo ironet init \
  --config /etc/ironet/config.toml \
  --state-dir /var/lib/ironet \
  --network-id "节点 A 输出的 network_id"
```

记录节点 B 的 `endpoint_id`。`identity.key` 是节点身份私钥，不应在节点之间复制或提交到版本库。

`init --non-interactive` 只生成身份和基础配置。该模式不会自动填写覆盖地址、已发布前缀或引导 peer，适合由配置管理系统后续写入配置的场景。

## 4. 写入静态配置

在两个节点上编辑 `/etc/ironet/config.toml`。以下是节点 A 的最小示例：

```toml
network_id = "两个节点相同的随机网络 ID"
identity_file = "/var/lib/ironet/identity.key"
discovery_enabled = true
node_interface = "ironet0"
node_addresses = ["21.0.0.1/32"]
advertised_prefixes = []

[routing]
isolate_overlay = true
transit_enabled = false
rule_priority = 10000
table = 211
allow_default_routes = false

[mesh]
enabled = true
max_peers = 12

[packet_policy]
enforce_overlay_prefixes = true

[[peers]]
name = "node-b"
endpoint_id = "节点 B 的 endpoint_id"
direct_addresses = ["203.0.113.22:4000"]
```

节点 B 使用同一个 `network_id`，把 `node_addresses` 改为 `21.0.0.2/32`，并把 `[[peers]]` 改为节点 A 的 endpoint ID 和公网地址：

```toml
[[peers]]
name = "node-a"
endpoint_id = "节点 A 的 endpoint_id"
direct_addresses = ["203.0.113.11:4000"]
```

`mesh.enabled = true` 时，节点通过签名 Presence 交换远端地址和前缀归属。固定 peer 只承担引导和固定邻接角色。仅使用静态拓扑时，先用 `ironet route import --defer` 导入远端前缀归属，再把 `mesh.enabled` 设为 `false` 并为 peer 配置 `allowed_source_prefixes`；完整示例见 [配置参考](配置参考.md#静态拓扑与独立路由文件)。

如果公网地址不是默认监听端口，可在顶层设置 `bind_addresses`，例如：

```toml
bind_addresses = ["0.0.0.0:4000"]
```

## 5. 校验、密封并启动

配置文件和其 BLAKE3 摘要必须匹配。每次手工修改 TOML 后，依次执行：

```bash
sudo ironet validate --config /etc/ironet/config.toml
sudo ironet seal-config --config /etc/ironet/config.toml
sudo ironet doctor --config /etc/ironet/config.toml
sudo systemctl enable --now ironet
```

前两条命令分别检查配置和写入 `/etc/ironet/config.toml.blake3`。`doctor` 会检查 Linux 平台、`/dev/net/tun`、`CAP_NET_ADMIN`、`iproute2`、转发 sysctl、固定 peer 的底层路由，以及配置的 DERP 服务器。

## 6. 验证

在节点 A 上检查守护进程和覆盖路径：

```bash
sudo ironet health
sudo ironet peers
sudo ironet status --output json
sudo ironet ping 21.0.0.2
sudo ironet trace 21.0.0.2
```

预期结果：

- `health` 退出状态为 0；
- `peers` 显示节点 B 已连接，或在建立连接期间显示重连状态；
- `ping` 至少收到一个应用层探测响应；
- `trace` 显示目标节点；
- `ip addr show ironet0` 显示本节点配置的覆盖地址。

`ping` 和 `trace` 使用覆盖层的认证控制协议，不使用主机 ICMP，因此结果对应 FlowRouter 实际选择的直连或多跳路径。

## 7. 将本地 LAN 接入覆盖网络

假设节点 A 后方 LAN 为 `192.168.10.0/24`。在节点 A 配置中加入：

```toml
advertised_prefixes = ["192.168.10.0/24"]
```

然后重新校验、密封并重载：

```bash
sudo ironet validate --config /etc/ironet/config.toml
sudo ironet seal-config --config /etc/ironet/config.toml
sudo systemctl reload ironet
```

需同时确认 LAN 侧主机的回程路由能回到节点 A。守护进程负责覆盖网与本地接口之间的策略路由；它不替代 LAN 的地址规划、网关配置或防火墙规则。
