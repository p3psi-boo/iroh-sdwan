# 配置参考

主配置使用 TOML，默认路径为 `/etc/ironet/config.toml`。守护进程加载配置时同时校验同目录的 `config.toml.blake3`。静态远端路由单独保存在 `identity_file` 同目录的 `routes.toml`（默认 `/var/lib/ironet/routes.toml`），由 `route` CLI 管理，不参与主配置密封。修改主配置后必须执行：

```bash
sudo ironet validate --config /etc/ironet/config.toml
sudo ironet seal-config --config /etc/ironet/config.toml
sudo systemctl reload ironet
```

完整带注释样例见 [`config/example.toml`](../config/example.toml)。配置使用 `deny_unknown_fields`，拼写错误或未支持字段会使校验失败。

未修改默认行为时，`path_selection`、`routing`、`mesh`、`packet_policy`、`fec` 和
`observability` 均可省略。一个节点的最小主配置只需要网络身份和地址：

```toml
network_id = "共享网络 ID"
identity_file = "/var/lib/ironet/identity.key"
node_addresses = ["21.0.0.1/32", "fd42:6972:6f68::1/128"]
```

## 顶层字段

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `network_id` | 是 | 无 | 同一覆盖网络的共享随机 ID。不同网络不得复用。 |
| `identity_file` | 是 | 无 | 节点身份私钥路径。权限应为 `0600`。 |
| `bind_addresses` | 否 | 空 | 固定 iroh UDP 监听地址；每个 IPv4/IPv6 地址族最多一项。 |
| `excluded_underlay_prefixes` | 否 | 空 | 禁止作为直连底层路径端点的 IP 前缀。 |
| `quic_auto_tune` | 否 | `true` | 根据协商能力和实时路径遥测自动选择 MTU、pacing、缓冲、lane 和 FEC；显式参数作为上限。 |
| `discovery_enabled` | 否 | `true` | 是否启用底层地址发现和已连接 peer 辅助打洞；全静态默认路由模式必须设为 `false`。该字段不会自动开启 iroh relay。 |
| `attachment` | 否 | `tun` | 本地数据面接入；`none` 为不创建 TUN 的纯用户态中转节点。 |
| `tun_mtu` | 否 | `65535` | Linux TUN 的固定逻辑 MTU，最小 `1280`。数据面启用 GSO/GRO，将内核交付的大报文拆成批次；QUIC frame 上限再按实时路径 MTU 独立调整。 |
| `max_frame_size` | 否 | `1400` | 初始 QUIC UDP 负载的安全上限，最小 `256`。 |
| `udp_segmentation_offload` | 否 | `false` | 是否使用 UDP segmentation offload 批量发送 QUIC datagram。仅在主机 UDP 协议栈和网卡支持时开启。 |
| `quic_send_buffer_bytes` | 否 | `131072` | 每连接 QUIC DATAGRAM 发送缓冲区，范围 8 KiB–8 MiB。 |
| `quic_receive_buffer_bytes` | 否 | `8388608` | 每连接 QUIC DATAGRAM 接收缓冲区，范围 64 KiB–64 MiB。 |
| `quic_data_lanes` | 否 | `2` | 每 peer 可自动协商的 QUIC 连接上限；默认仍从单 lane 起步，仅在持续高速、低丢包时扩展，范围 1–8。 |
| `quic_congestion_controller` | 否 | `cubic` | `cubic`、`bbr3`、`passthrough` 或 `adaptive`。 |
| `quic_initial_rtt_millis` | 否 | `100` | QUIC 初始 RTT 估计，范围 1–10000 ms。 |
| `quic_initial_mtu` | 否 | `1400` | 初始 UDP payload MTU，范围 1200–1452。 |
| `quic_mtu_discovery_enabled` | 否 | `false` | 启用 DPLPMTUD；发生拥塞诱发的黑洞回退后重新探测 MTU。 |
| `quic_mtu_black_hole_cooldown_millis` | 否 | `10000` | MTU 黑洞回退后的重新探测等待时间，范围 1–600 秒。 |
| `quic_keep_alive_millis` | 否 | `1000` | 连接和路径 keepalive 周期，范围 100–60000 ms。 |
| `quic_passthrough_window_bytes` | 否 | `16777216` | passthrough 模式的固定在途窗口。 |
| `quic_passthrough_pacing_mbps` | 否 | 空 | passthrough 模式的可选发送速率上限。 |
| `quic_adaptive_initial_mbps` | 否 | `850` | adaptive 模式初始 pacing。 |
| `quic_adaptive_min_mbps` | 否 | `100` | adaptive 模式 pacing 下限。 |
| `quic_adaptive_max_mbps` | 否 | `950` | adaptive 模式 pacing 上限。 |
| `quic_adaptive_loss_backoff_bps` | 否 | `50` | adaptive 每次拥塞事件的退避基点数；100 表示 1%。 |
| `quic_pacing_quantum_bytes` | 否 | `8192` | passthrough/adaptive pacer 的发送 quantum，范围 1200–65536 字节。 |
| `node_interface` | 否 | `ironet0` | 守护进程管理的 Linux 接口名，最长 15 字节。 |
| `node_addresses` | 否 | 空 | 当前节点的覆盖地址前缀，例如 `21.0.0.1/32`。 |
| `advertised_prefixes` | 否 | 空 | 由当前节点发布的 LAN 或服务前缀。 |

`network create` 和 `join` 自动为每个 TUN 节点分配一个 `/32` Overlay IPv4
地址和一个 `/128` Overlay IPv6 地址。`node_addresses` 和
`advertised_prefixes` 不能与静态远端前缀重叠。固定 peer 的
`direct_addresses` 也不能落在任何覆盖前缀中。

## 底层地址族偏好 `[path_selection]`

```toml
[path_selection]
prefer = "ipv6"
```

`prefer` 可设为 `ipv6` 或 `ipv4`，默认 `ipv6`。IPv4、IPv6 可用路径会同时
保留并测量，一次只选择一条承载业务。偏好只在黑洞记录、丢包和 RTT 接近时
作为决策条件；另一地址族明显更好时仍会被选择。该配置只控制节点邻接的底层
传输地址族，不改变 Overlay 数据包的地址族。

## 节点信息 `[node_info]`

节点信息由 trace 响应返回，用于识别路径上的节点；其编码总长度上限为 800 字节。

```toml
[node_info]
name = "branch-a"
description = "分支节点"

[node_info.metadata]
site = "site-a"
role = "branch"
```

`name` 不能为空。拥有 TUN 地址时，trace 会按目标地址族自动选取 `node_addresses` 中该地址族的第一个地址作为探测源和回包地址；同一地址族有多个地址时，配置顺序决定选中的地址。纯中转节点可保留 `node_info` 用于目录识别。

## 无 TUN 中转

```toml
attachment = "none"

[routing]
transit_enabled = true
```

该模式不打开 `/dev/net/tun`，不修改 Linux 路由表，也不要求
`CAP_NET_ADMIN`。它不能声明 `node_addresses` 或 `advertised_prefixes`，但会继续
在 QUIC 邻接之间执行源策略、hop-limit 递减和用户态 FlowRouter 转发。

## relay `[relay]`

`relay` 配置节点邻接的底层 relay，而不是覆盖层路由。默认
`iroh_relay_enabled = false`，因此只使用直连 UDP、DERP 和已连接节点的覆盖层
中转。节点可以先通过 DERP、固定直连地址或现有覆盖邻接建立正式连接，再由连接
内部的定向候选交换执行打洞；升级到直连或回退 DERP 不替换 Ironet 会话。

UPnP、PCP、NAT-PMP、host IPv4/IPv6 和 peer 观察候选使用同一个 iroh UDP endpoint。
`ironet status` 的 `network` 和 `network_candidate` 行，以及 status JSON/Prometheus，
会公开端口映射候选、IPv6、`mapping_varies_by_destination` 与 NAT64
前缀。已连接 peer 只在候选集合变化时发送经过过滤的定向候选提示，不再依赖
固定周期碰运气。

至少应配置一个具有固定可达 `direct_addresses` 的 bootstrap peer；生产环境
建议配置两个处于不同故障域的 bootstrap/transit peer。

### 可选 iroh relay（显式开启）

```toml
[relay]
iroh_relay_enabled = true
urls = [
  "https://relay-1.example.net",
  "https://relay-2.example.net",
]
```

`iroh_relay_enabled` 默认为 `false`。只有显式设为 `true` 后才能配置 `urls`、
`discovery_urls` 或 peer 的 `relay_urls`；`urls` 至少需要两个 URL。它与 DERP
可同时配置。

只想分离发现端点的配置也必须至少两个，并且不得与 `urls` 重复：

```toml
[relay]
iroh_relay_enabled = true
discovery_urls = [
  "https://qad-1.example.net",
  "https://qad-2.example.net",
]
```

iroh 的 QAD 与 relay 注册共用 relay map，因此 `discovery_urls` 也会成为加密的
fallback relay。配置任一自建 URL 集合会取代 N0 默认集合。

### DERP

```toml
[relay]
servers = [
  "https://derp-1.example.net/derp",
  "https://derp-2.example.net/derp",
]
```

DERP 服务器 URL 只允许 `http` 或 `https`，路径为根路径或 `/derp`。`servers` 为空时不启用 DERP；非空时每个固定 peer 必须填写独立的 `derp_public_key`。显式开启 iroh relay 后，`relay_urls` 可与 DERP 同时配置。初始化时传入 `--derp-server URL` 会生成本节点的 DERP 身份文件并输出公钥。

## 固定 peer `[[peers]]`

固定 peer 用于引导连接或固定邻接。mesh 开启时，前缀归属和对端转发能力由签名 Presence 动态获得。

```toml
[[peers]]
name = "public-a"
endpoint_id = "64 位十六进制 iroh endpoint ID"
transit_enabled = false
direct_addresses = ["203.0.113.10:4000"]
relay_urls = [
  "https://relay-1.example.net",
  "https://relay-2.example.net",
]
```

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | 是 | 无 | 唯一且非空的本地名称。 |
| `endpoint_id` | 是 | 无 | 对端 iroh endpoint ID。不能是本节点 ID。 |
| `transit_enabled` | 否 | `false` | mesh 关闭时，允许该 peer 作为未直接拥有目标前缀的首跳。mesh 开启时以对端 Presence 为准。 |
| `direct_addresses` | 否 | 空 | 固定 UDP 地址。端口不可为 0。 |
| `relay_urls` | 否 | 空 | 此 peer 的 iroh relay URL；仅在 `relay.iroh_relay_enabled = true` 时允许，提供时至少两个。 |
| `derp_public_key` | `relay.servers` 非空时是 | 无 | 该 peer 的 32 字节十六进制 DERP 公钥。 |
| `allowed_source_prefixes` | 静态模式且启用源校验时是 | 空 | 此邻接允许送达的远端源前缀，必须与 `routes.toml` 的某项完全一致。 |

同一配置中，peer 名称、endpoint ID、直连地址和 DERP 公钥不得重复。

## 私有点到点承载 `[[links]]`

当 IEPL/IPLC/L2 隧道交付内网地址或端口转发时，把节点身份留在 `[[peers]]`，
把不应公开的传输路径放入独立的 pairwise link：

```toml
[[peers]]
name = "branch-b-private"
endpoint_id = "B 的 endpoint ID"
transit_enabled = true

[[links]]
id = "iepl-ab-01"
name = "iepl-ab"
peer_id = "B 的 endpoint ID"
class = "private-circuit"
visibility = "pairwise"
dial = "active" # B 端使用 passive；也可以两端使用 auto
exclusive = true
fallback = false
local_bind = "10.255.0.1:4000"
remote_addresses = ["10.255.0.2:4000"]
allowed_local_prefixes = ["10.255.0.1/32"]
allowed_remote_prefixes = ["10.255.0.2/32"]
auth_key = "两端共享的 64 位十六进制随机值"
```

private link 的 locator 永远不进入 NodeRecord/Presence、候选交换或 relay；对应
peer 也不能同时填写 `direct_addresses`、`relay_urls` 或 `derp_public_key`。运行时只
接受配置的 IP:port 和正向前缀白名单，QUIC 迁移到公网、relay、DERP 或其他地址会
关闭连接。V1 Session 还会验证 `id + auth_key` 的 pairwise proof。

## 静态拓扑与独立路由文件

从动态 mesh 切换到全静态拓扑时，先在 `init` 生成且已经密封的默认配置上用
`route import --defer` 写入路由，再关闭 mesh、补充 peer 源前缀，最后执行
`seal-config` 和 `reload`。这样路由文件与主配置可以分开变更，任何时刻都不会
把尚未密封的主配置交给守护进程。

关闭 mesh 后，需要显式记录每个远端前缀的所有者，并在对应 peer 上允许该来源：

```toml
[mesh]
enabled = false

[packet_policy]
enforce_overlay_prefixes = true

[[peers]]
name = "transit-b"
endpoint_id = "B 的 endpoint ID"
transit_enabled = true
direct_addresses = ["203.0.113.20:4000"]
allowed_source_prefixes = ["21.0.0.3/32", "192.168.30.0/24"]

```

将路由清单写成便于生成的文本，每行是“最终所有者 endpoint ID + 一个或多个前缀”：

```text
# site-c.routes
C_ENDPOINT_ID 21.0.0.3/32 192.168.30.0/24
```

然后导入、查看或删除：

```bash
# 少量路由可直接使用配置中的 peer 名称
sudo ironet route add 21.0.0.3/32 192.168.30.0/24 --owner branch-c

# 批量导入前先预览变更
sudo ironet route import ./site-c.routes --dry-run
sudo ironet route import ./site-c.routes
sudo ironet route list
sudo ironet route list --output json
sudo ironet route remove 192.168.30.0/24
# 也可按 peer 名称或 endpoint ID 一次删除该所有者的全部前缀
sudo ironet route remove branch-c
```

`route import` 默认与现有路由合并，重复项保持幂等；加 `--replace` 可完整替换。
传入 `-` 可从标准输入导入。`route list` 会把已配置 peer 的名称和完整 endpoint ID
一起展示；`list/remove` 还提供 `ls/rm` 短别名。
导入和删除会先按主配置完成统一校验，再原子写入 `/var/lib/ironet/routes.toml`，
并自动请求运行中的守护进程 reload。守护进程未运行时记录仍会保存并在下次启动时生效；
也可显式加 `--defer`。旧的 `--no-reload` 仍作为兼容别名。导入文件也可以使用持久化文件的 TOML 格式：

```toml
version = 1

[[route]]
endpoint_id = "C 的 endpoint ID"
prefixes = ["21.0.0.3/32", "192.168.30.0/24"]
```

`endpoint_id` 表示前缀的最终所有者，不表示中转节点。两个不同所有者的前缀不能重叠。中转节点只在 `peers.transit_enabled = true` 时可被选为首跳。

## 路由 `[routing]`

```toml
[routing]
isolate_overlay = true
transit_enabled = false
rule_priority = 10000
table = 211
allow_default_routes = false
nat_enabled = true
# max_egress_mbps = 80
```

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `isolate_overlay` | `true` | 使用 FlowRouter 专用的 Linux 策略路由表隔离覆盖流量。 |
| `transit_enabled` | `false` | 允许本节点在两个覆盖 peer 之间转发数据包。它不控制 peer 到本地节点或本地 LAN 的访问。 |
| `rule_priority` | `10000` | Linux 策略路由规则优先级，范围 `2..32765`。 |
| `table` | `211` | FlowRouter 使用的 Linux 路由表；不可使用 `0`、`253`、`254`、`255`。 |
| `allow_default_routes` | `false` | 是否允许 `0.0.0.0/0` 或 `::/0` 作为覆盖前缀。 |
| `nat_enabled` | `true` | 对从 `ironet0` 进入并转发到本节点 `advertised_prefixes` 的流量执行源 NAT（IPv4 MASQUERADE / IPv6 NAT66），使 LAN 主机无需配置远端覆盖前缀的回程路由。设为 `false` 可恢复纯路由模式。 |
| `max_egress_mbps` | 未设置 | 本机 overlay 出口的策略上限，不参与 Presence，也不表示链路容量。 |

默认路由要求同时满足：`allow_default_routes = true`、`discovery_enabled = false`、`relay.urls`、`relay.discovery_urls` 和 `relay.servers` 均为空，并且每个固定 peer 都有 `direct_addresses` 或 pairwise link。这限制了默认路由对本机底层可达性的影响。

## mesh `[mesh]`

```toml
[mesh]
enabled = true
max_peers = 12
```

`enabled` 为 `true` 时，节点在认证 peer 间交换签名 Presence，并在固定 peer 与自动选择邻接总数不超过 `max_peers` 的前提下建立连接。自动邻接可使用 direct 或 DERP locator 建立正式连接，再在原连接内尝试直连；显式开启 iroh relay 后也可使用其 locator。`max_peers` 范围为 `1..32`；Presence 目录条目本身不占用邻接名额。

## 数据包源校验 `[packet_policy]`

```toml
[packet_policy]
enforce_overlay_prefixes = true
```

开启时，接收的数据包源地址必须来自合法的覆盖前缀。mesh 关闭时，必须同时导入静态路由并为每个 peer 提供 `allowed_source_prefixes`；否则统一校验会失败。

## FEC `[fec]`

```toml
[fec]
enabled = false
data_shards = 8
recovery_shards = 2
block_timeout_millis = 20
decoder_ttl_millis = 2000
```

FEC 是可选的系统化 Reed-Solomon 数据报保护。接收端可以解析 FEC 封装，即使本端发送 FEC 被关闭。可靠的流式 DERP 路径不使用 FEC。

| 字段 | 范围 | 说明 |
| --- | --- | --- |
| `data_shards` | `2..64` | 一个块中的数据分片数量。 |
| `recovery_shards` | `1..32` | 每个块的恢复分片数量。 |
| `block_timeout_millis` | `1..1000` | 等待同一块剩余分片的时间。 |
| `decoder_ttl_millis` | `block_timeout_millis..60000` | 接收端保留解码状态的时间。 |

## 可观测性 `[observability]`

```toml
[observability]
status_file = "/run/ironet/status.json"
metrics_file = "/run/ironet/metrics.prom"
report_interval_secs = 10
```

守护进程以原子方式写入 JSON 状态文件和 Prometheus 文本文件。两个路径不得相同，报告间隔必须大于零。文件中包含节点、peer、路径、队列、容量估计、探测与错误计数。

## 配置更新方法

### 手工编辑并重载

适用于小范围且可直接在节点上审阅的变更：

```bash
sudoedit /etc/ironet/config.toml
sudo ironet validate --config /etc/ironet/config.toml
sudo ironet seal-config --config /etc/ironet/config.toml
sudo systemctl reload ironet
```

### 原子安装候选文件

适用于配置管理系统生成候选文件的场景：

```bash
sudo ironet install-config \
  --source /etc/ironet/config.toml.candidate \
  --config /etc/ironet/config.toml
sudo systemctl reload ironet
```

该命令校验候选文件、原子替换活动配置、保留 `config.toml.previous` 及其摘要。回退时执行：

```bash
sudo ironet rollback-config --config /etc/ironet/config.toml
sudo systemctl reload ironet
```
