# 配置参考

配置使用 TOML，默认路径为 `/etc/iroh-sdwan/config.toml`。守护进程加载配置时同时校验同目录的 `config.toml.blake3`。修改配置后必须执行：

```bash
sudo iroh-sdwan validate --config /etc/iroh-sdwan/config.toml
sudo iroh-sdwan seal-config --config /etc/iroh-sdwan/config.toml
sudo systemctl reload iroh-sdwan
```

完整带注释样例见 [`config/example.toml`](../config/example.toml)。配置使用 `deny_unknown_fields`，拼写错误或未支持字段会使校验失败。

## 顶层字段

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `network_id` | 是 | 无 | 同一覆盖网络的共享随机 ID。不同网络不得复用。 |
| `identity_file` | 是 | 无 | 节点身份私钥路径。权限应为 `0600`。 |
| `bind_addresses` | 否 | 空 | 固定 iroh UDP 监听地址；每个 IPv4/IPv6 地址族最多一项。 |
| `forbidden_underlay_prefixes` | 否 | 空 | 禁止作为直连底层路径端点的 IP 前缀。 |
| `discovery_enabled` | 否 | `true` | 是否启用底层发现。全静态默认路由模式必须设为 `false`。 |
| `tun_mtu` | 否 | `65535` | TUN 接口的自动上限，最小 `1280`。运行时会根据路径情况调整。 |
| `max_frame_size` | 否 | `1400` | 初始 QUIC UDP 负载的安全上限，最小 `256`。 |
| `node_interface` | 否 | `isw0` | 守护进程管理的 Linux 接口名，最长 15 字节。 |
| `node_addresses` | 否 | 空 | 当前节点的覆盖地址前缀，例如 `21.0.0.1/32`。 |
| `advertised_prefixes` | 否 | 空 | 由当前节点发布的 LAN 或服务前缀。 |

`node_addresses` 和 `advertised_prefixes` 不能与静态远端前缀重叠。固定 peer 的 `direct_addresses` 也不能落在任何覆盖前缀中。

## 节点信息 `[node_info]`

节点信息由 trace 响应返回，用于识别路径上的节点；其编码总长度上限为 800 字节。

```toml
[node_info]
name = "branch-a"
description = "分支节点"

[node_info.metadata]
site = "site-a"
role = "branch"
```

`name` 不能为空，且配置 `node_info` 时 `node_addresses` 至少包含一个地址。trace 会按目标地址族自动选取 `node_addresses` 中该地址族的第一个地址作为探测源和回包地址；同一地址族有多个地址时，配置顺序决定选中的地址。

## relay `[relay]`

`relay` 选择节点邻接使用的中继方式，而不是覆盖层路由方式。

### 默认 iroh relay

```toml
[relay]
mode = "default"
```

### 禁用 relay

```toml
[relay]
mode = "disabled"
```

禁用 relay 后应为所有固定 peer 配置可达的 `direct_addresses`。使用默认路由前缀时必须采用此模式。

### 自定义 iroh relay

```toml
[relay]
mode = "custom"
urls = [
  "https://relay-1.example.net",
  "https://relay-2.example.net",
]
```

自定义模式至少需要两个 URL。固定 peer 可省略自己的 `relay_urls` 以继承这里的 URL，也可以自行配置至少两个 URL。

### DERP

```toml
[relay]
mode = "derp"
servers = [
  "https://derp-1.example.net/derp",
  "https://derp-2.example.net/derp",
]
```

DERP 服务器 URL 只允许 `http` 或 `https`，路径为根路径或 `/derp`。每个固定 peer 必须填写独立的 `derp_public_key`，且不得同时配置 `relay_urls`。初始化时传入 `--derp-server URL` 会生成本节点的 DERP 身份文件并输出公钥。

## 固定 peer `[[peers]]`

固定 peer 用于引导连接或固定邻接。mesh 开启时，前缀归属和对端转发能力由签名 Presence 动态获得。

```toml
[[peers]]
name = "public-a"
endpoint_id = "64 位十六进制 iroh endpoint ID"
transit_enabled = false
direct_addresses = ["203.0.113.10:4000"]
relay_urls = [
  "https://relay-1.example.net",
  "https://relay-2.example.net",
]
```

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | 是 | 无 | 唯一且非空的本地名称。 |
| `endpoint_id` | 是 | 无 | 对端 iroh endpoint ID。不能是本节点 ID。 |
| `transit_enabled` | 否 | `false` | mesh 关闭时，允许该 peer 作为未直接拥有目标前缀的首跳。mesh 开启时以对端 Presence 为准。 |
| `direct_addresses` | 否 | 空 | 固定 UDP 地址。端口不可为 0。 |
| `relay_urls` | 否 | 空 | 此 peer 的 iroh relay URL，提供时至少两个。 |
| `derp_public_key` | DERP 模式时是 | 无 | 该 peer 的 32 字节十六进制 DERP 公钥。 |
| `allowed_source_prefixes` | 静态模式且启用源校验时是 | 空 | 此邻接允许送达的远端源前缀，必须与 `route_origins` 的某项完全一致。 |

同一配置中，peer 名称、endpoint ID、直连地址和 DERP 公钥不得重复。

## 静态拓扑

关闭 mesh 后，需要显式列出每个远端前缀的所有者，并在对应 peer 上允许该来源：

```toml
[mesh]
enabled = false

[packet_policy]
enforce_overlay_prefixes = true

[[peers]]
name = "transit-b"
endpoint_id = "B 的 endpoint ID"
transit_enabled = true
direct_addresses = ["203.0.113.20:4000"]
allowed_source_prefixes = ["21.0.0.3/32", "192.168.30.0/24"]

[[route_origins]]
endpoint_id = "C 的 endpoint ID"
prefixes = ["21.0.0.3/32", "192.168.30.0/24"]
```

`route_origins.endpoint_id` 表示前缀的最终所有者，不表示中转节点。两个不同所有者的前缀不能重叠。中转节点只在 `peers.transit_enabled = true` 时可被选为首跳。

## 路由 `[routing]`

```toml
[routing]
isolate_overlay = true
transit_enabled = false
rule_priority = 10000
table = 100
allow_default_routes = false
# max_egress_mbps = 80
```

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `isolate_overlay` | `true` | 使用 FlowRouter 专用的 Linux 策略路由表隔离覆盖流量。 |
| `transit_enabled` | `false` | 允许本节点在两个覆盖 peer 之间转发数据包。它不控制 peer 到本地节点或本地 LAN 的访问。 |
| `rule_priority` | `10000` | Linux 策略路由规则优先级，范围 `2..32765`。 |
| `table` | `100` | FlowRouter 使用的 Linux 路由表；不可使用 `0`、`253`、`254`、`255`。 |
| `allow_default_routes` | `false` | 是否允许 `0.0.0.0/0` 或 `::/0` 作为覆盖前缀。 |
| `max_egress_mbps` | 未设置 | 本机 overlay 出口的策略上限，不参与 Presence，也不表示链路容量。 |

默认路由要求同时满足：`allow_default_routes = true`、`discovery_enabled = false`、`relay.mode = "disabled"`，并且每个固定 peer 都有 `direct_addresses`。这限制了默认路由对本机底层可达性的影响。

## mesh `[mesh]`

```toml
[mesh]
enabled = true
max_peers = 12
```

`enabled` 为 `true` 时，节点在认证 peer 间交换签名 Presence，并在固定 peer 与自动选择的直接邻接总数不超过 `max_peers` 的前提下建立连接。`max_peers` 范围为 `1..32`；Presence 目录条目本身不占用邻接名额。

## 数据包源校验 `[packet_policy]`

```toml
[packet_policy]
enforce_overlay_prefixes = true
```

开启时，接收的数据包源地址必须来自合法的覆盖前缀。mesh 关闭时，必须同时提供 `route_origins` 和每个 peer 的 `allowed_source_prefixes`；否则配置校验会失败。

## FEC `[fec]`

```toml
[fec]
enabled = false
data_shards = 8
recovery_shards = 2
block_timeout_millis = 20
decoder_ttl_millis = 2000
```

FEC 是可选的系统化 Reed-Solomon 数据报保护。接收端可以解析 FEC 封装，即使本端发送 FEC 被关闭。可靠的流式 DERP 路径不使用 FEC。

| 字段 | 范围 | 说明 |
| --- | --- | --- |
| `data_shards` | `2..64` | 一个块中的数据分片数量。 |
| `recovery_shards` | `1..32` | 每个块的恢复分片数量。 |
| `block_timeout_millis` | `1..1000` | 等待同一块剩余分片的时间。 |
| `decoder_ttl_millis` | `block_timeout_millis..60000` | 接收端保留解码状态的时间。 |

## 可观测性 `[observability]`

```toml
[observability]
status_file = "/run/iroh-sdwan/status.json"
metrics_file = "/run/iroh-sdwan/metrics.prom"
report_interval_secs = 10
```

守护进程以原子方式写入 JSON 状态文件和 Prometheus 文本文件。两个路径不得相同，报告间隔必须大于零。文件中包含节点、peer、路径、队列、容量估计、探测与错误计数。

## 配置更新方法

### 手工编辑并重载

适用于小范围且可直接在节点上审阅的变更：

```bash
sudoedit /etc/iroh-sdwan/config.toml
sudo iroh-sdwan validate --config /etc/iroh-sdwan/config.toml
sudo iroh-sdwan seal-config --config /etc/iroh-sdwan/config.toml
sudo systemctl reload iroh-sdwan
```

### 原子安装候选文件

适用于配置管理系统生成候选文件的场景：

```bash
sudo iroh-sdwan install-config \
  --source /etc/iroh-sdwan/config.toml.candidate \
  --config /etc/iroh-sdwan/config.toml
sudo systemctl reload iroh-sdwan
```

该命令校验候选文件、原子替换活动配置、保留 `config.toml.previous` 及其摘要。回退时执行：

```bash
sudo iroh-sdwan rollback-config --config /etc/iroh-sdwan/config.toml
sudo systemctl reload iroh-sdwan
```
